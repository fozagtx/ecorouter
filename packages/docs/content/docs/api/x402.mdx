---
title: x402 Validation
description: What validateChallenge checks, in order.
---

`validateChallenge(challenge, mandate, maxSpend, executionId?)` returns the accepted amount in atomic units, or throws. It runs these checks in exact order, from `x402/validate.ts`:

1. **Supported requirements.** `x402Version === 2`, `scheme === "exact"`, `network === "stellar:testnet"`, `asset === mandate.asset`, and a non-empty `payTo` string. Failure: `InvalidPaymentChallengeError`.
2. **Amount format.** `amount` is a string matching `^\d+$`. Failure: `InvalidPaymentChallengeError`.
3. **Positive amount.** `BigInt(amount) > 0`. Failure: `InvalidPaymentChallengeError`.
4. **Mandate not revoked.** `mandate.revoked` is false. Failure: `MandateRevokedError`.
5. **Mandate not expired.** `mandate.expiresAt` is greater than the current Unix time in seconds. Failure: `MandateExpiredError`.
6. **Local policy.** `amount <= parseUsdc(maxSpend)`. Failure: `PolicyExceededError`.
7. **Mandate limits.** `amount <= mandate.maxPaymentAtomic` and `amount <= mandate.remainingAtomic`. Failure: `MandateExceededError`.

Note the ordering consequences: a revoked or expired mandate throws before any policy check, and the local `maxSpend` cap is evaluated before the on-chain mandate caps.

Inside `router.execute`, validation failures do not throw. They silently disqualify that provider; a provider is only removed from the eligible set.

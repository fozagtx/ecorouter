The SDK does not ship a Stellar transport implementation. You provide a `PaymentClient` that reads mandate state and submits the authorized transfer. The router treats its return value and its errors precisely.

## SignedPayment and SettlementReceipt

`SignedPayment` is `{ payload: string; transactionHash?: string }`. The payload is sent back to the provider in the `payment-signature` header.

`SettlementReceipt` is `{ transactionHash: string }`. The hash is returned in `result.payment.transactionHash`.

## Error contract

Throw the typed errors for definite failures:

- `PaymentAuthorizationError` when signing or authorization definitively failed.
- `PaymentSettlementError` when the transfer definitively failed on-chain.

Both propagate unchanged and mark the execution `failed`, so the same `executionId` can be retried.

**Any other thrown value marks the execution `settlement_unknown`** and the router throws `PaymentSettlementUnknownError`, because the payment may have succeeded. A `settlement_unknown` execution id cannot be retried; retrying throws. Only throw a generic error when settlement truly is ambiguous.

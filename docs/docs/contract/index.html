Smart Account Contract

The ecorouter-account Soroban contract and its mandate enforcement.

contracts/ecorouter-account is a no_std Soroban smart account (crate type cdylib). It holds funds, stores a spending mandate, and authorizes outbound transfers through the __check_auth custom account interface. All types and behaviors below come from contracts/ecorouter-account/src/lib.rs.

The Mandate

A single mandate is stored in instance storage under DataKey::Mandate; the owner address is stored under DataKey::Owner.

What __check_auth enforces

When a session key signs an invocation that requires this account's auth, the contract checks, in order:

  1. A mandate exists (MandateNotFound), is not revoked (MandateRevoked), and has not expired (MandateExpired).
  2. The signer public key equals mandate.session_public_key (WrongSigner), and the Ed25519 signature verifies over the payload.
  3. Exactly one authorization context, and it must be a Context::Contract call (UnsupportedInvocation). Administrative functions are structurally impossible for the session key.
  4. The called contract equals mandate.asset (WrongAsset), the function is transfer with exactly 3 arguments (UnsupportedInvocation).
  5. The transfer source is the account contract itself (WrongSource) and amount > 0 (InvalidAmount).
  6. amount <= mandate.max_payment (PaymentAboveMaximum).
  7. spent + amount <= mandate.total_limit (AllowanceExceeded), using checked arithmetic.

On success the contract increments spent and emits a payment authorized event carrying asset, recipient, amount, new spent, and remaining allowance.

Errors

AccountError: AlreadyInitialized (1), NotInitialized (2), InvalidAmount (3), InvalidExpiration (4), MandateNotFound (5), MandateRevoked (6), MandateExpired (7), WrongSigner (8), UnsupportedInvocation (9), WrongAsset (10), WrongSource (11), PaymentAboveMaximum (12), AllowanceExceeded (13).

Building and deploying

The contract is a standard Soroban cdylib crate. Build and deploy with the Stellar CLI (stellar contract build, stellar contract deploy), then call initialize with the owner address and create_mandate to bind a session key, asset, and limits. The repository does not ship deploy scripts; see the Soroban docs for network-specific commands.

[TypeScript]
import { Arbiter } from "@arbiter-ai/sdk";

// 1. Initialize local routing runtime
const arbiter = new Arbiter({
  account: process.env.ARBITER_ACCOUNT!,         // Soroban smart account
  sessionSecret: process.env.ARBITER_SESSION_KEY!, // Ed25519 session secret
  paymentClient: localStellarClient,             // Injected Testnet signer
  providers: [
    { id: "search-a", capability: "web.search", endpoint: "https://a.example/search", qualityScore: 0.94 },
    { id: "search-b", capability: "web.search", endpoint: "https://b.example/search", qualityScore: 0.82 }
  ]
});

// 2. Execute capability request bounded by policy
const response = await arbiter.execute({
  executionId: "query-" + Date.now(),
  capability: "web.search",
  input: { query: "latest lithium carbonate prices" },
  policy: { maxSpendUsdc: "0.05", minimumQuality: 0.85 }
});

console.log(response.output.results);          // Strict normalized search results
console.log(response.decision.providerId);      // Winning provider
console.log(response.payment.transactionHash); // Stellar Testnet receipt

// 02_CORE_ARCHITECTURE

BUILT FOR AUTONOMOUS PURCHASING

Four foundational properties designed to make AI agents safe, deterministic, and economically rational.

[01 // INFRASTRUCTURE] ▓▒░ LOCAL

Zero Hosted Control Plane

Private keys, signing material, and routing decisions remain completely inside the developer's process. There is no Arbiter telemetry server, custodial wallet, database, or subscription gateway.

[02 // ROUTING_MATH] ▓▒░ EXACT

Deterministic Economic Cost

Arbiter never consults an LLM to select vendors. Providers are ranked strictly by priceAtomic / (qualityScore × successRate) using exact integer arithmetic, resolving ties by lexical ID.

[03 // SMART_ACCOUNT] ▓▒░ ONCHAIN

Soroban Mandate Boundary

The smart account on Stellar independently verifies session signatures through __check_auth, enforcing cumulative budgets, single-payment caps, expiration timestamps, and revocation flags.

[04 // NORMALIZATION] ▓▒░ SCHEMA

Strict Output Normalization

Provider responses are parsed and verified into invariant schema types. Upstream agents interact solely with clean data structures, protecting workflows against vendor API mutations.

// 04_EXECUTION_LADDER

ONE REQUEST. ONE DECISION.

Every step executes deterministically without centralized coordination or custodial exposure.

01 DISCOVERY_CHALLENGE Arbiter sends an unpaid probe to configured providers; candidates return HTTP 402 headers with signed price requirements. [CONCURRENT]
02 POLICY_VALIDATION Sanitizes recipients, validates testnet asset parity, checks local maxSpend boundaries, and parses atomic BigInt amounts. [LOCAL_CHECK]
03 ECONOMIC_SELECTION Computes priceAtomic / (qualityScore × successRate); lowest score wins. Ties break strictly by lexical provider ID. [DETERMINISTIC]
04 ONCHAIN_SETTLEMENT Session signer authorizes exact transfer; Soroban contract validates allowance, cumulative spend, and active mandate status. [ONCHAIN_GATE]
05 OUTPUT_NORMALIZATION Winning provider verifies settlement proof and streams payload; SDK normalizes response into strict WebSearchResult. [VERIFIED_OK]
